00. БЫСТРАЯ ПЕРЕДАЧА НОВОМУ ЧАТУ — ПРОЧИТАЙ В ПЕРВУЮ ОЧЕРЕДЬ
================================================================================
Пользователь разрабатывает WT Mod Manager для Windows: Python 3.12, PySide6, PyInstaller --onefile, установщик Inno Setup. Есть сопутствующий сайт GitHub Pages (docs/) и Supabase backend для аккаунтов, медиа, модов и ZIP-сканирования. Цель — стабильная, проверяемая, безопасная программа и красивый интерфейс без удаления существующих функций. Код живёт в GitHub, не нужно присылать вручную ZIP, когда доступен GitHub connector.

Главное пожелание: перед каждым изменением читать АКТУАЛЬНЫЕ файлы проекта; менять точечно, не сокращать UI и не удалять функции; работать через новую ветку + PR + CI; проверять безопасность секретов; выпускать версию только после успешной Windows-сборки. Все релизные номера согласовывать между src/update_checker.py, installer/WTModManager.iss, installer/release-notes.txt и .github/workflows/build-windows-exe.yml, а также тестами.

Последнее проверенное: Beta 12 в GitHub Releases, 5 ассетов (portable, setup, SHA256SUMS, build-info, sbom). CI Windows установка/запуск/удаление, тесты восстановления и trust, SBOM, Sigstore-проверка — зелёные. В последующем документальном улучшении удалены только кэш-файлы *.pyc из Git (исходники сохранены). Это НЕ новый desktop релиз: версия остаётся beta.12.

КРИТИЧНО: текущий публичный релиз помечен UNSIGNED. Sigstore attestation != Authenticode, SHA-256 != цифровая подпись, код проекта не может легально «заставить» Windows доверять новой программе. Нет гарантии убрать SmartScreen без настоящего доверенного сертификата и репутации издателя.

Моды: Supabase Edge wtmm-mod-scan работает с 1 ZIP за выполнение и приватной очередью, защищённой Vault token. Сканирует структуру и CRC, ограничивает ZIP-бомбы, сомнительное ведёт на manual review. Кэш SHA структурной проверки на 30 дней не означает AV clean. Автоматически одобрять не следует. Отдельный ClamAV/GitHub Actions pipeline требует индивидуальной активации и секретов.

Не встраивать ни VirusTotal private API key, ни service_role, ни GitHub signing PFX в клиентский JS/EXE/репозиторий. VT запросы — через server Edge function или локально в DPAPI (личный ключ); если ранее опубликованный ключ раскрывался в чате — считать раскрытым и перевыпустить на стороне провайдера.

02. ИСТОРИЯ И ЗАДАЧИ ПО СИСТЕМАМ — ЧТО СДЕЛАНО

A. РАННИЕ БЕТЫ И UI
A1. Централизованный UI на PySide6. Главное окно, трей, автоматическое распознавание запуска War Thunder, меню и переходы. Ответственность: src/main.py, ui/main_window.py.
A2. Персонализация: темы Dark/Light/System, акцент, шрифты, плавность, набор сохранённых пресетов, пользовательские цвета. Ответственность: ui/settings_page.py, ui/theme_engine.py, ui/appearance.py, ui/personalization_panels.py, src/settings_store.py.
A3. Иконки в assets/icons/Black и assets/icons/White; логотип assets/icons/Logotip/LogotipProject.png; выбирать корректные ресурсы для текущей темы. Ответственность: ui/icon_assets.py.
A4. Моды прицелов, звуков, камуфляжей, локальный просмотр/плейер и WAV waveform. Ответственность: ui/sights_page.py, ui/sounds_page.py, ui/media_page.py, ui/audio_waveform.py, src/audio_analysis.py.
A5. Импорт в War Thunder только при подтверждении и проверке допустимых путей, когда игра закрыта; резервная копия и возможность ручного rollback. Ответственность: src/game_mod_installer.py и ui/game_install_ui.py.
A6. Локальные настройки и моды отдельно для каждого пользователя Windows: %LOCALAPPDATA%/WTModManager; не писать в Program Files. Ответственность: src/profile_paths.py, src/settings_store.py.
A7. В Windows установленная версия и portable отличаются файлом installer/wtmm.installed и механизмом is_installed_app(); не путать пути двух режимов.

B. УСТАНОВЩИК И ОБНОВЛЕНИЯ (исторические Beta 9-10, последующий Beta 11)
B1. Единый PyInstaller --onefile EXE; основные ресурсы входят в EXE, старую папку _internal при upgrade можно убрать контролируемо. Ответственность: tools/build_windows_exe.py, installer/WTModManager.iss.
B2. Inno Setup с брендированными иллюстрациями, совместимостью upgrade, ярлыками, импортом portable, режимом расширенной установки, выбором Stable/Beta; удаление по умолчанию сохраняет пользовательские моды и настройки. Ответственность: installer/WTModManager.iss, tools/build_installer_assets.py.
B3. Скруглённое изображение мастера готовится как asset без некрасивых прозрачных чёрных углов: исходник — assets/icons/Logotip/LogotipProject.png, генератор tools/build_installer_assets.py; реальный результат проверять визуально на Windows.
B4. Закрепление на панели задач не делается скрытым Explorer hack из установщика. На поддерживаемых Windows официальный запрос из запущенного приложения с участием пользователя; при недоступности — инструкция. Ответственность: src/taskbar_pin.py, tools/taskbar/taskbar_pin.cpp, src/main.py, installer/WTModManager.iss.
B5. Проверка релиза через официальный GitHub API и digest SHA-256, лимит размера, HTTPs, контроль редиректов, проверка MZ, ограниченное скачивание и запуск только после согласия. Ответственность: src/update_checker.py, ui/update_ui.py.
B6. Portable обновление: отдельный updater-процесс дожидается завершения старого EXE, копирует backup, проверяет SHA-256, атомарно заменяет. Ручной rollback после повторной проверки backup. Ответственность: src/portable_updater.py.
B7. Installed обновление: проверенный WTModManager-Setup.exe запускает обычный Inno Setup мастер; не пытаться самовольно переписать установленный EXE. Ответственность: src/installed_updater.py.
B8. Автоматическая проверка наличия обновлений — каждые 10 минут при включённой опции; сама установка не происходит без согласия. Локальные уведомления сохраняются отдельно. Ответственность: ui/update_ui.py, src/update_notifications.py.
B9. Согласование версии по всем файлам и запрет повреждённого релиза. В .github/workflows/build-windows-exe.yml сборка и публикация разделены на два job; публикация разрешена из main после всех проверок.
B10. Сертификат: tools/sign_windows_release.ps1 применяет Authenticode при наличии доверенного PFX и GitHub Secrets. Если сертификата нет — публикуемый EXE честно unsigned. Не смешивать название релиза 'Verified' с наличием сертификата.
B11. Созданы SHA256SUMS.txt, build-info.json (SHA, commit, version, workflow URL, signed flag), проверка их целостности tools/release_integrity.py; отдельно GitHub attestation/Sigstore подтверждает происхождение.
B12. Workflow .github/workflows/release-checksums.yml больше НЕ перезаписывает SHA256SUMS после публикации: только скачивает, проверяет sha256sum --check. Это снижает риск поменять историю хешей.
B13. Дополнительная упаковка UPX отключена; делать прозрачно проверяемые бинарные файлы, а не пытаться скрывать сигнатуры от антивирусов.

C. BETA 12 — НАДЁЖНОСТЬ И TRUST
C1. src/crash_recovery.py создаёт marker текущего сеанса, замечает unexpected shutdown и локально хранит до 8 санитизированных отчётов. Тип ошибки, имя функции и номер строки; исключены exception messages, локальные пути и токены.
C2. src/main.py вызывает start_session(), встраивает sys/thread exception hooks, при нормальном выходе отмечает clean_exit; после неожиданного выхода показывает предложение диагностики, особенно после --updated.
C3. ui/trust_panel.py показывает отдельный WT Trust Center; SHA-256 и PowerShell Get-AuthenticodeSignature идут через src/trust_center.py в background thread, не грузят GUI.
C4. В UI есть ручное копирование очищенного crash report; отчёт никуда не отправляется автоматически.
C5. src/update_checker.py проверяет свободное место под скачивание + резервный запас и отсутствие symlink для updates cache; нехватка места останавливает скачивание, не удаляя моды.
C6. ui/online_page.py позволяет выбрать Stable или Beta после установки. Канал хранится в пользовательском update-channel.json; Stable не означает автоматического выпуска Beta как Stable.
C7. docs/trust.html + docs/js/trust-center.js показывают релизы с публичными Github digest, ссылками на checksum и build-info; подтверждение Authenticode локально, а не «галочка по названию файла».
C8. tools/build_sbom.py создаёт sbom.cdx.json (CycloneDX, Python dependencies, не список всех нативных компонентов); публикуется вместе с остальными 4 ассетами, проверяется в CI.
C9. .github/dependabot.yml — автоматические предложения обновления pinned Python deps/GitHub Actions; .github/workflows/dependency-health.yml — еженедельный pip-audit. Не применять Dependabot PR без CI и ревью.
C10. Версия Beta 12 прошла Windows CI тесты установки/удаления, файловой подписи/метаданных, SBOM, SHA/Sigstore и опубликована. Пример ссылки выше.

D. СЕРВЕРНЫЙ СКАНЕР ZIP-МОДОВ
D1. Пользователь загружает ZIP через docs/mods/mods.js в закрытый Supabase Storage; серверная запись попадает в private.wtmm_mod_scan_queue.
D2. Cron wtmm-mod-scan-serial вызывает Edge worker с приватным токеном Vault (не в браузере). PostgreSQL advisory lock + atomic claim предотвращают параллельную выдачу нескольких заданий.
D3. Один запуск worker обрабатывает один ZIP. При 5 заявках они идут последовательно. Статусы queued / scanning / checked / review / blocked / error.
D4. zip.ts проверяет структуру центрального каталога/локальные заголовки/CRC, опасные пути, symlink, лимиты распаковки и расширений, вложенные ZIP и исполняемые сигнатуры. По документации: 20 MiB ZIP, максимум 250 элементов, 80 MiB декомпрессии.
D5. Ложные срабатывания: неизвестные безобидные расширения, короткие 'MZ' или '#!' не приравниваются автоматически к вирусам. При неоднозначности stage=review, после полной CRC проверки. Реальный Windows PE-header или запрещённый executable блокируется.
D6. Нельзя публиковать без ручного решения администратора. Для review нужен администратор с MFA и дополнительным подтверждением; scan_status blocked блокирует публикацию.
D7. private.wtmm_scan_cache на 30 дней хранит только SHA-256+scanner engine version и структурные verdict checked/review, не VirusTotal clean. При изменении правил обязательно менять SCANNER_VERSION.
D8. private очередь имеет server-only priority (0..2) с бонусом возраста, не позволяя свежим приоритетным заданиям вечно обгонять старые.
D9. Временные ошибки повторяются с backoff и максимум 3 попытками; живой Edge server отвечает 200/processed:0/reason:idle на пустую очередь.
D10. docs/mods/mods.js показывает файловое количество, статус CRC/структуры и отдельно антивирусные ограничения; структурная проверка НЕ гарантирует отсутствия вредоноса.
D11. Отдельный workflow ClamAV / scan-mod-packages.yml — опциональный, требуются secrets и запуск. Не выдавать наличие кода за работающее постоянное антивирусное сканирование.
D12. VirusTotal интеграция — lookup ПО ХЕШУ через сервер/DPAPI; не все detection являются true positive. Не отправлять файлы на публичные сторонние сервисы без согласия. Не встроить раскрытый API key в JS/EXE.

E. САЙТ / СООБЩЕСТВО / АККАУНТЫ
E1. GitHub Pages docs/ публикует сайт, страница загрузки связывается с GitHub Releases.
E2. Account, profile, community, support, contact и mod catalogue реализованы через JS frontend + Supabase auth/database/Edge. Обычный пользователь не получает admin rights из localStorage/client claims.
E3. RLS, rate limits, MFA authorization, Guardian модерация оформлены SQL файлами docs/database/. Применение каждого файла в repo НЕ означает что он автоматически запущен на сервере.
E4. Windows desktop связка: Supabase Edge desktop bridge + токен пары под Windows DPAPI, не повторное использование веб-токена.

06. КОНКРЕТНЫЕ СХЕМЫ ДАННЫХ, ФАЙЛЫ ПОЛЬЗОВАТЕЛЕЙ И ГРАНИЦЫ

  %LOCALAPPDATA%\WTModManager\recovery\crashes\crash-*.json — очищенные отчёты
  %LOCALAPPDATA%\WTModManager\accounts\... — изолированная библиотека привязанных аккаунтов
  DPAPI защищает device pairing token в Windows user context; не копировать токены в публичную папку.

Supabase database (основные актуальные имена):
  public.wtmm_mods — каталог модов, triage_status, triage_note, scan_status и т.п.
  private.wtmm_mod_scan_queue — atomically claimed задания одного worker.
  private.wtmm_scan_cache — SHA-256 / engine-version / checked или review / timestamp.
  wtmm_scan_claim(), wtmm_scan_finish() — service-role RPC для очереди.
  wtmm_scan_cache_get(), wtmm_scan_cache_put() — service-role only RPC.
  cron.job 'wtmm-mod-scan-serial' — вызов Edge раз в минуту.
  Edge wtmm-mod-scan -> POST, x-wtmm-internal-token (секрет только в Supabase Vault).
  Edge wtmm-vt-lookup -> SHA/VT безопасный серверный gateway.

Не изменять статус approval напрямую из клиента в обход RLS / server guards.
Не доверять user_metadata JWT для прав администратора. Отдельные SQL
скрипты под docs/database/ могут быть историческими миграциями, не «накатить все
по алфавиту» без изучения зависимостей и сверки текущей схемы. Для секретов
использовать server-side secrets manager, а не docs/assets/config.
