# WT Mod Manager: локальные камуфляжи по технике и обновление приложения

Дата: 19 ноября 2026.
Ветка: feature/vehicle-camouflage-workflow-20261119.
Зависимость: feature/one-click-in-app-updates-20261119 (PR #59).
ВАЖНО: опубликованная Beta 13 ещё не содержит эти изменения.

## Реализовано на уровне приложения

- Работа с существующей вкладкой «Камуфляжи», а не отдельное новое приложение.
- Выбор источника: готовый пакет с .blk и текстурами или одна картинка
  для простого масштабируемого узора, если шаблон игры позволяет.
- Выбор техники по шаблонам, которые игра сама создала в UserSkins.
  Проверка совпадения имени vehicle_id.blk с выбранной техникой.
- Название в приложении: «WT Mod камуфляж №001» и соответствующий ID машины.
- Создание отдельной папки UserSkins/WT_Mod_Camouflage_001__vehicle_id.
  Следующие наборы получают номера 002, 003 и т.д.; оригинальный template_
  не перезаписывается.
- Перед записью в папки игры: предпросмотр, разрешение человека, проверка
  конфликтов и уже существующий механизм отката. Запись пакета ограничена
  допустимыми текстурами и .blk; символические ссылки запрещены.
- Картинка через Pillow конвертируется в 1024x1024 TGA с сохранением пропорций.
  Поддержан только один очевидный масштабируемый replace_tex; для сложных
  UV-текстур требуется готовый корректный комплект, картинка сама не достаточна.
- Менеджер показывает локальные установленные наборы и их привязку к технике.
  После установки в самой игре нужен Refresh списка пользовательских
  камуфляжей и выбор соответствующего набора.

## Видимость и ограничения War Thunder

Официальный источник: https://wiki.warthunder.com/cdk/creation_camo
Обычные локальные пользовательские камуфляжи видны ТОЛЬКО владельцу.
Другие участники взвода с WTMM или без него не видят их автоматически.
Публичное отображение доступно отдельным камуфляжам, включённым самой
игрой (например, через официальную программу авторов/маркет); оно не
создаётся изменением файлов на личном компьютере. Нельзя обещать иначе.

В игре название может отличаться от текста «WT Mod камуфляж №001»
и зависеть от названия папки. Совместимость текстур зависит от реального
шаблона и версии игрового клиента.

## Система обновлений

PR #59 использует существующий Windows Inno Setup и проверенные официальные
GitHub Release файлы. После одного подтверждения установленная копия
скачивает обновление внутри приложения, сверяет размер и SHA-256, показывает
процент, обновляет текущую папку и перезапускает GUI.
Первый переход с опубликованной Beta 13 ещё может потребовать старый
интерактивный мастер. Portable-EXE имеет отдельный проверяемый механизм.
Подробности: docs/md/WTMM_ONE_CLICK_UPDATES_2026-11-19.md на ветке PR #59.

## Виртуальная приёмка (без реальной игры)

Проверочный сценарий создаёт временную фальшивую папку War Thunder с
config.blk, UserSkins/template_ussr_kv_1_l_11/ussr_kv_1_l_11.blk и TGA.
Тест создаёт собственную Rainbow PNG и проверяет: определение техники,
ограниченную конвертацию, отдельный набор №001, нетронутый исходный
шаблон, безопасную запись, историю и откат. Дополнительно проверяются
несовместимые .blk, неоднозначные слои и символические ссылки.

Эти тесты проверяют ЛОГИКУ на Windows, но НЕ подтверждают реальное
отображение в движке War Thunder. GitHub Actions не запускает саму игру.
Для полноценного ручного E2E на ПК, где действительно установлена игра,
нужно проверить меню внешнего вида и правильность текстур на настоящем
шаблоне, а также отдельно убедиться, что обновление программы сохранило
моды и настройки. Никогда не писать в реальные папки игры без согласия.

## Выпуск

Не перезаписывать тег v1.3.0-beta.13. Следующий релиз требует отдельного
номера, полного Windows CI и ручной проверки. Факт успешной сборки сам по
себе не доказывает работоспособность всех игровых текстур.
