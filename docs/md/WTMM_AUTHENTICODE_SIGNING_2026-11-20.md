# WT Mod Manager — доверенная подпись Windows Authenticode

Дата: 20 ноября 2026. Ветка: feature/camo-layer-selector-signing-readiness-20261120.
Статус: подготовка пайплайна. Последняя опубликованная Beta 14 — UNSIGNED.
**Нельзя честно объявить EXE подписанным, пока издатель не получит
настоящий сертификат или не подключит подходящий сервис подписи.**

## Для чего нужна подпись

Подпись Microsoft Authenticode идентифицирует издателя и позволяет Windows
проверить целостность программы и доверенную цепочку сертификата.
Она **не гарантирует безопасность**, не отключает Defender и не обещает
отсутствие предупреждений SmartScreen (репутация приложения отдельна).
SHA-256 и GitHub Attestations остаются дополнительными, но другими проверками.

Справка Microsoft:
- https://learn.microsoft.com/en-us/windows/desktop/seccrypto/signtool
- https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options
- https://learn.microsoft.com/en-us/windows/win32/seccrypto/time-stamping-authenticode-signatures

## Способы получить доверенную подпись

1. Сертификат подписи ПО издателя от доверенного центра сертификации (CA)
   с подтверждённой личностью/организацией и подходящим EKU Code Signing.
   Способ работы с ключом зависит от провайдера: у современных сертификатов
   может быть аппаратное, облачное или неэкспортируемое хранилище.
2. Профессиональный сервис подписания (например, Azure Artifact Signing).
   Для него требуется отдельная интеграция аутентификации и подписи; наш
   скрипт PFX-импорта **пока не поддерживает** удалённое хранилище ключа.
3. Для подходящих открытых проектов SignPath Foundation может предоставить
   бесплатную подпись по своей программе и после отбора. Это не автоматическая
   выдача сертификата и не обещание одобрения.
4. Самоподписанный сертификат годится для локальных тестов, **не для публичного
   доверия Windows**. Нельзя скрывать этот факт или просить пользователей
   выключать SmartScreen/Defender.

Если издателю нужна проверка личности или договор, она должна проходить
официально самим законным владельцем (или с участием родителя/опекуна,
если это требуется). Никаких обходов процедур.

## Уже реализованная автоматизация для сертификата PFX

В сборке уже есть три подписываемых артефакта:
- build/wtmm_taskbar.dll (до PyInstaller);
- dist/WTModManager.exe (до Inno Setup);
- dist/WTModManager-Setup.exe (после Inno Setup).

Секреты задаются только в репозитории GitHub:
Settings → Secrets and variables → Actions → Repository secrets.
Не загружать PFX, пароль, base64 или секреты в Git, файлы сайта, переписку,
комментарии PR и публичные логи.

Для **действительно экспортируемого легитимного PFX**:
- WTMM_SIGN_PFX_BASE64: base64 содержимого файла PFX (GitHub Secret);
- WTMM_SIGN_PFX_PASSWORD: пароль сертификата (GitHub Secret);
- WTMM_SIGN_CERT_THUMBPRINT: 40-значный SHA-1 thumbprint **публичного
  сертификата** издателя, GitHub Repository variable. Используется лишь
  для выбора проверенной личности; сигнатура самого EXE — SHA-256.
- WTMM_REQUIRE_AUTHENTICODE: строка true, GitHub Repository variable,
  включать после настройки и успешной проверки рабочего сертификата.

Важное примечание: certificate SHA-1 thumbprint служит идентификатором
сертификата, но **не** означает использование слабой SHA-1 подписи:
фактическая подпись и метка времени требуют /fd SHA256 и /td SHA256.

Все три шага подписывания запускаются лишь для доверенного push в main,
не для PR. Подписывание требует реальной цепочки Windows Valid, сверяет
сертификат с закреплённым thumbprint, проверяет через SignTool verify /pa,
а закрытый ключ после подписи удаляется из временной папки runner.
Включённый WTMM_REQUIRE_AUTHENTICODE запрещает выпуск неподписанной сборки,
а не создаёт сертификат автоматически.

Публичный сертификат после подписывания проверяется локально в Windows:
«Свойства → Цифровые подписи» или Get-AuthenticodeSignature.
В релизном build-info.json статус authenticode.signed должен быть true,
а publisher — совпадать с легитимным издателем.

## Что можно сделать без сертификата

- Продолжать тестировать приложение и камуфляжи в виртуальных Windows CI.
- Публиковать только честно помеченные unsigned beta, если переменная
  WTMM_REQUIRE_AUTHENTICODE выключена.
- Подать заявку на подходящий официальный способ подписывания. Приложение
  не может самостоятельно получить доверенную подпись.
